## Contradictions resolved

1. **"The 90-day chart has no window label" (owner brief) vs NI-03.** Refuted in part: the chart IS labelled "90-day vs SPY" (book.tsx:305-306). The real defect is that the XIRR pair loses its "annualized" qualifier exactly when the benchmark line renders (book.tsx:288-295), and the 95-day holding period renders nowhere. Fix the XIRR labelling, leave the chart label alone.
2. **Is the XIRR display defensible?** Arithmetically yes (NI-15 refuted the integer-styling claim: 0.6863 - 0.2963 = 0.3900 exactly), presentationally no: +68.6%/yr is a 3.8x extrapolation of a 95-day book, 5 days past the MIN_DAYS_TO_ANNUALIZE gate, undisclosed. Resolution: W1 adds the always-on qualifier and holding period (NI-03/PR-02); W2 demotes the XIRR pair to a caption/popover under the 90-day chart (RD-08), keeping one vs-SPY answer on the card face.
3. **03 wants buckets, 07 wants adjustable score weights.** Decided: buckets now (DU-01/DU-02, W1 foundation); weights stay code constants (AG-08 itself concurs). A single preset toggle may ship only after IN-05's calibration read view proves the score predicts action. Weights are deferred, not scheduled.
4. **CH-14/CH-27 say delete `AsOfLine` as dead code; PR-08/PR-11 say adopt it.** Resolution: adopt. `AsOfLine` was built for exactly the tape-header as-of slot and is the cheapest source-name affordance on the page. The other three dead `_viz` files (primitives, feed-row, bars) and `HealthRadar` are deleted per the dead-payload row.
5. **Registry declares a 60s tape refresh; the architecture map repeats it as behavior; 08 and 14 prove it is unwired (ST-08/CH-18), and 09 proves wiring it as-is would rebuild every engine per minute (PF-05).** Resolution: the behavior does not exist today; W5 wires a light quotes-only endpoint for the tape and either implements or deletes the registry policy fields. No audit's "60s live" claim should be treated as current behavior.
6. **RD-13 says cut the unrendered `threats`/`attribution`/`calibration` slices; PR-06/DU-16 say render them.** Resolution: split. Threat quantities (worst case -20.2%, VaR) and attribution rows are exactly the missing provenance decomposition, so they get rendered (PR-06, W1). `timeline`, `intelligence`, `calibration`, `pulse.radar`, and `portfolioSummary` have no consumer or planned consumer and are cut from the wire (W5).
7. **"Actions 1 vs 19 open vs 3 unread" - which number is wrong?** None: each counter is correct for its own collection (NI-04 verdict). The defect is labelling and wiring (KPI named "Actions", anchor named "action-center", prompt label "UNREAD ALERTS" for notifications). Resolution: rename and re-anchor in W1; W2's restructure then leaves exactly one count (the queue's).
8. **Count-up animation: "the hero's signature moment" (code) and reduced-motion compliant (AC-08) vs DU-11/AC-07/BM-06 (renders false values 760 ms per load; false change signal).** Resolution: cut it. Motion is reserved for actual data arrival (the brief stream landing), per the benchmark's rejection of ambient animation.
9. **Long read: benchmark pattern #13 says "keep the AI note collapsed by default forever"; RD-03/IA-06 say it is ~80% restatement and should go.** Resolution: retire it from the page in W2 (`visible: false`). It re-earns a context-shelf or linked-page slot only after W4's prompt rewrite (LQ-07) makes it capable of saying things that appear nowhere else. Both audits agree the current content has no claim to any position.
10. **LQ-05 non-determinism: no temperature control is possible (hosted providers ignore the field).** Resolution: do not chase determinism at the provider layer; make the cache key strict enough (LQ-04) that re-wording only happens when facts change.
11. **Radar/queue duplication is defended in code comments on both sides (RD-14) as "deliberately a different scale".** Resolution: the ownership split wins (02's single-mention map, 03's merge verdict, 06's restructure): the queue owns decision kinds, the radar owns signals; the signals feeder is removed from the queue and dismissals propagate to radar tiles.
12. **ST-06 (hero needs an onboarding empty state) vs W2 (the hero module dies).** Resolution: do not build onboarding into a module scheduled for retirement; ST-06's directive-verbs requirement transfers to the post-restructure Zone 1 strip and the queue empty state. The row stays W5, scoped to the surviving surfaces.
13. **Severity of the brief's "grounding": 00/04 describe a grounding gate as a working defense; 05 shows only the headline is checked and the gate certifies stale data as fresh.** Resolution: 05 is authoritative (it traced `buildBriefFacts` exhaustively); the gate is treated as headline-only and clock-blind until LQ-01/LQ-02 land.
